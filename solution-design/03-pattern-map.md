# Pattern Map — Lake

Rust (edition 2021) → Zig. The translation is non-trivial because the source relies heavily on Rust's ownership system (`Drop` for RAII), `unsafe` blocks for C FFI, and `Arc`-based shared atomics for cross-thread coordination. Zig has no ownership model, no `unsafe` boundary (all C interop is direct), and no reference counting — it uses explicit `defer` for cleanup, direct C function calls without a safety boundary, and explicit lifetime management. The core challenge is replacing Rust's compiler-enforced safety with Zig's philosophy of explicit, auditable resource management.

## Pattern inventory

| # | Source pattern | Idiom / example | Frequency | Structural | Risk |
|---|---------------|----------------|-----------|-----------|------|
| 1 | `unsafe` blocks for C FFI calls | `unsafe { zmq_sys::zmq_msg_recv(ptr, sock, 0) }` — wrapping every ZMQ C call in unsafe | 31 instances, 6 files | Yes | Low — Zig calls C directly, no safety boundary needed |
| 2 | `unsafe impl Send + Sync` on raw pointer wrapper | `unsafe impl Send for Context {}` — declaring ZMQ context pointer safe to share across threads | 1 instance | Yes | Medium — Zig has no Send/Sync; thread safety is the programmer's responsibility |
| 3 | RAII via `impl Drop` for resource cleanup | 6 Drop impls: `Context::drop` calls `zmq_ctx_term`, `Socket::drop` calls `zmq_close`, `Message::drop` calls `zmq_msg_close`, `Relay::drop` joins thread, `Metrics::drop` joins thread, `Program::drop` sends sd_notify | 6 instances | Yes | Medium — must systematically replace with `defer` or explicit `deinit` methods |
| 4 | `Arc<AtomicBool>` for cross-thread running flag | `prog.running.clone().store(false, Ordering::Relaxed)` — shared boolean for shutdown signal | Pervasive (5 files) | Yes | Medium — Zig has `std.atomic.Value` but no `Arc`; pointer sharing must be explicit |
| 5 | `Arc<AtomicUsize>` for lock-free counter | `self.messages.fetch_add(1, Ordering::Relaxed)` — atomic message counter incremented by relay, read/reset by metrics | 1 instance | Yes | Low — direct equivalent in `std.atomic.Value(usize)` |
| 6 | `std::thread::spawn` with `move` closure | `thread::spawn(move \|\| { ... })` — captures config values, Arc clones, context into closure | 2 instances | Yes | Medium — Zig uses `std.Thread.spawn` with explicit context struct passed as pointer |
| 7 | `JoinHandle` in `Option` for deferred join | `child_thread: Option<thread::JoinHandle<()>>` + `.take().unwrap().join()` in Drop | 2 instances | Yes | Low — Zig uses `thread.join()` in explicit deinit |
| 8 | `mem::MaybeUninit` for uninitialized signal sets | `let mut sigset_memspace = mem::MaybeUninit::uninit()` for `libc::sigfillset` | 2 instances | Yes | Low — Zig uses `std.mem.zeroes` or `undefined` for C struct initialization |

| 10 | Raw pointer manipulation (`*mut c_void`) | `pub underlying: *mut c_void` / `pub sock: *mut c_void` as struct fields | Pervasive in socket/message layer | Yes | Low — Zig uses `*anyopaque` or typed `*zmq_ctx_t` directly from `@cImport` |

| 12 | `libc::raise(SIGTERM)` as inter-thread exit signal | Worker threads raise SIGTERM to unblock main thread's sigwait | 2 instances | Yes | Low — same C call from Zig; but design could be improved with explicit signalling |
| 13 | `#[cfg(target_os)]` conditional compilation | Platform-specific `mem_bytes()` (linux vs macos), `notify()` (unix vs non-unix) | 4 attributes | Yes | Medium — Zig uses `comptime` and `builtin.os.tag` for platform dispatch |
| 14 | `log` facade with custom `impl Log` trait | `Logger` struct implementing `log::Log` trait for formatted stdout output | 1 impl | Yes | Medium — Zig has `std.log` with custom log function, but different API shape |
| 15 | `std::error::Error` + `Display` + `Debug` trait impls | Standard Rust error interop on the `Error` enum | 3 impls | No | Low — Zig errors are a different paradigm (error sets), no trait system |
| 16 | `ffi::CString` for null-terminated C strings | `ffi::CString::new(endpoint.as_bytes()).unwrap()` before passing to `zmq_bind`/`zmq_connect` | 2 instances | Yes | Low — Zig string literals are already null-terminated; `std.fmt.bufPrint` + sentinel for dynamic strings |
| 17 | Builder-like config with env fallbacks | `Configuration::load()` reads env vars with `env_string`/`env_i32` helpers | 1 struct | No | Low — trivial to rewrite in any language |
| 18 | `#[must_use]` attribute | Compiler hint on constructors | 3 instances | No | Low — no Zig equivalent needed; Zig already warns on unused return values |
| 19 | `#[allow(clippy::*)]` lint suppressions | Suppressing cast warnings, precision loss, uppercase acronyms | 7 instances | No | Low — Rust-specific; irrelevant to Zig |
| 20 | Manual date formatting from UNIX epoch | Custom year/month/day calculation from `SystemTime::now()` in `logger.rs` | 1 block | No | Low — Zig `std.time.epoch` + manual or `std.fmt` formatting |

## Pattern mapping

| # | Source pattern | Target equivalent | Semantic gap | Mitigation | ADR |
|---|---------------|------------------|-------------|------------|-----|
| 1 | `unsafe` FFI blocks | Direct C function calls via `@cImport` | None — Zig has no unsafe/safe boundary; all C calls are equally "unsafe" by Rust standards but naturally expressed in Zig | Zig's explicit error handling (`catch`, `try`) provides safety at the API boundary instead of the call boundary | [ADR-01-03](adr/01-platform/adr-01-03-zmq-binding.md) |
| 2 | `unsafe impl Send + Sync` | No equivalent needed | Zig has no type-level thread-safety markers; the programmer asserts thread safety by design | Document thread-safety invariants in comments; confine shared mutable state to atomic types | [ADR-02-03](adr/02-runtime/adr-02-03-threading-coordination.md) |
| 3 | RAII `impl Drop` | `defer` statements + explicit `deinit()` methods | Zig's `defer` is lexically scoped to the enclosing block, not to struct lifetime. Drop impls that trigger on any scope exit (including error paths, early returns, and ownership transfer) have no direct equivalent for struct fields. | Use `deinit()` methods called explicitly at cleanup sites. For ZMQ resources (context, socket, message), use `defer obj.deinit()` immediately after creation. For thread-owning structs (Relay, Metrics), call `deinit()` explicitly in main's shutdown sequence. | [ADR-01-03](adr/01-platform/adr-01-03-zmq-binding.md), [ADR-02-02](adr/02-runtime/adr-02-02-lifecycle-shutdown.md) |
| 4 | `Arc<AtomicBool>` shared flag | `*std.atomic.Value(bool)` passed as pointer to threads | Zig has no reference counting. `Arc` combines atomic reference counting with shared ownership. In Zig, the caller must ensure the atomic outlives all threads. | Allocate the atomic in the owner (main), pass a pointer to spawned threads. The owner is responsible for joining threads before the atomic goes out of scope. Explicit lifetime, no refcount overhead. | [ADR-02-03](adr/02-runtime/adr-02-03-threading-coordination.md) |
| 5 | `Arc<AtomicUsize>` shared counter | `*std.atomic.Value(usize)` passed as pointer | Same as pattern 4 — no refcount, pointer sharing | Same as pattern 4 | [ADR-02-03](adr/02-runtime/adr-02-03-threading-coordination.md) |
| 6 | `thread::spawn` + `move` closure | `std.Thread.spawn(.{}, threadFn, .{context_ptr})` | Zig threads take a function pointer and a context argument, not a closure. All captured state must be packed into an explicit struct passed as a single pointer. | Define a `ThreadContext` struct containing all values the thread needs. Pass a pointer to it. Zig's compile-time type safety ensures the argument types match. | [ADR-02-03](adr/02-runtime/adr-02-03-threading-coordination.md) |
| 7 | `Option<JoinHandle>` + join-in-Drop | `std.Thread` stored directly + `thread.join()` in `deinit()` | Zig has no Option-wrapped join. The thread handle is just a value; joining is an explicit call. | Store `std.Thread` in the struct. Call `thread.join()` in `deinit()`. No Option unwrap needed. | [ADR-02-02](adr/02-runtime/adr-02-02-lifecycle-shutdown.md) |
| 8 | `MaybeUninit` for C struct init | `std.mem.zeroes(T)` or `= undefined` | Zig's `undefined` is equivalent to MaybeUninit (uninitialized memory). `std.mem.zeroes` is safer when the C API accepts zero-initialized structs. | Use `std.mem.zeroes(std.c.sigset_t)` for signal sets (POSIX allows zero-init). Use `undefined` only where the C API explicitly initializes the memory (e.g., `zmq_msg_init`). | [ADR-02-02](adr/02-runtime/adr-02-02-lifecycle-shutdown.md) |
| 9 | `mem::transmute` lifetime extension | Direct pointer use | None — the transmute is a workaround for Rust's borrow checker. Zig has no borrow checker; a pointer to C-owned memory is valid as long as the C library says it is. | Use `std.mem.span` or slice from C pointer directly. | [ADR-01-03](adr/01-platform/adr-01-03-zmq-binding.md) |
| 10 | `*mut c_void` raw pointers | `*anyopaque` or typed C pointers | None — `@cImport` generates typed pointers from C headers. Where the C API uses `void*`, Zig uses `*anyopaque`. | Use `@cImport` generated types. Avoid manual `*anyopaque` where typed alternatives exist. | [ADR-01-03](adr/01-platform/adr-01-03-zmq-binding.md) |
| 11 | `libc::signal` / `libc::sigwait` | `std.c.sigaction` / `std.c.sigwait` or `std.os.linux` equivalents | None — same POSIX API, called directly | Use `std.c` or `std.os.linux` wrappers for signal handling. Same semantics. | [ADR-02-02](adr/02-runtime/adr-02-02-lifecycle-shutdown.md) |
| 12 | `libc::raise(SIGTERM)` for thread exit coordination | Eliminated — `zmq_ctx_shutdown` + atomic running flag replace inter-thread SIGTERM | Semantic gap resolved: ADR-02-02 decided to replace the `raise(SIGTERM)` pattern entirely with `zmq_ctx_shutdown` for deterministic shutdown. Worker threads no longer raise signals. | `zmq_ctx_shutdown` interrupts blocking `zmq_msg_recv` via `ETERM`. The running flag signals the metrics thread. No inter-thread signal needed. | [ADR-02-02](adr/02-runtime/adr-02-02-lifecycle-shutdown.md) |
| 13 | `#[cfg(target_os)]` | `if (comptime builtin.os.tag == .linux)` | Zig's comptime conditionals are equivalent in capability. The syntax differs but the semantics are the same — dead code is eliminated at compile time. | Use `const builtin = @import("builtin")` and comptime `if` for platform dispatch. | [ADR-02-04](adr/02-runtime/adr-02-04-observability.md) |
| 14 | `log` facade + custom `impl Log` | `std.log` with custom `log_fn` | Zig's `std.log` uses a module-level `pub const std_options` with a `logFn` field. The API shape differs (no trait, no boxed logger), but the capability is equivalent. | Define `pub const std_options = .{ .logFn = customLogFn }` in the root source file. Implement `customLogFn` with the same timestamp + colored level format. | [ADR-02-04](adr/02-runtime/adr-02-04-observability.md) |
| 15 | `Error`/`Display`/`Debug` trait impls | Zig error set + format function | Zig errors are a fundamentally different concept — they are compile-time-known sets, not runtime enum values. ZMQ errno values are runtime integers, which don't map to Zig error sets directly. | See "Unmappable patterns" below. | [ADR-01-03](adr/01-platform/adr-01-03-zmq-binding.md) |
| 16 | `ffi::CString` null-termination | Zig string literals (null-terminated by default) or `std.fmt.bufPrint` + sentinel | Zig string literals are `*const [N:0]u8` — null-terminated. For dynamic strings (e.g., formatted endpoints), use `std.fmt.bufPrintZ` which produces sentinel-terminated slices. | Use `std.fmt.bufPrintZ` for `tcp://0.0.0.0:{port}` formatting. No allocation needed — use a stack buffer. | [ADR-02-01](adr/02-runtime/adr-02-01-relay-loop.md) |
| 20 | Manual date formatting | `std.time.epoch.EpochSeconds` + manual calc or `std.fmt` | Zig's standard library has `std.time.epoch.EpochSeconds` with `.getEpochDay()` and `.getDaySeconds()`. This is a closer-to-stdlib approach than the manual calculation in Rust. | Use `std.time.epoch.EpochSeconds` for year/month/day decomposition. Less manual arithmetic, same result. | [ADR-02-04](adr/02-runtime/adr-02-04-observability.md) |
| 21 | Pointer cast chain for signal handler | Zig function pointer coercion | Zig function pointers are first-class and cast to C function pointer types naturally via `@ptrCast`. | Define the signal handler as `fn handler(sig: c_int) callconv(.C) void {}` and pass directly. | [ADR-02-02](adr/02-runtime/adr-02-02-lifecycle-shutdown.md) |
| 22 | `zmq_msg_t::default()` | `std.mem.zeroes(c.zmq_msg_t)` + `zmq_msg_init` | Direct equivalent — `@cImport` provides the struct type, zero-init before `zmq_msg_init`. | `var msg = std.mem.zeroes(c.zmq_msg_t); _ = c.zmq_msg_init(&msg);` | [ADR-02-01](adr/02-runtime/adr-02-01-relay-loop.md) |

## Unmappable patterns

| # | Source pattern | Frequency | Why unmappable | Proposed workaround | Impact |
|---|---------------|-----------|---------------|--------------------|---------| 
| 1 | Rust ownership + borrow checker enforced memory safety | Pervasive (entire codebase) | Zig has no ownership model and no borrow checker. Rust's compile-time guarantee that references are valid, that data races on non-atomic types are impossible, and that double-frees cannot occur has no equivalent in Zig. | Discipline: use `defer` for all resource cleanup, use atomic types for all shared state, avoid shared mutable non-atomic state entirely. The codebase is small (~400 lines) so manual auditing is feasible. Code review practices must substitute for compiler enforcement. | Reliability regression risk — bugs that Rust's type system would catch at compile time may become runtime bugs in Zig. Mitigated by the small codebase size, the simplicity of the data flow (stateless relay), and the existing blackbox test suite. |
| 2 | `Arc` (atomic reference counting for shared ownership) | 4 uses (running flag, metrics counter, relay handle, metrics handle) | Zig has no reference counting primitive in its standard library. `Arc` in Rust combines heap allocation, atomic refcount, and shared ownership in a single type. Zig has none of these as a unit. | Eliminate the need for refcounting by restructuring ownership: allocate shared state (atomics) in the owner (main), pass raw pointers to threads, ensure threads are joined before shared state is freed. This is safe because the program has a clear linear lifecycle: start → run → signal → join → cleanup. | Architectural simplification — fewer allocations, no refcount overhead. The constraint is that the owner must outlive all borrowers, which is naturally true in this program's lifecycle. |
| 3 | Rust `Error` trait ecosystem (Error + Display + Debug + From) | 1 Error type, 3 trait impls | Zig's error system uses compile-time error sets (`error{...}`) which cannot carry runtime payloads. The current Rust `Error` enum carries ZMQ errno values and produces human-readable messages via `zmq_strerror`. Zig error sets cannot hold a runtime integer. | Two-layer approach: (1) use a Zig error set for control flow (`error{SocketError, ContextError, ...}`), (2) separately call `zmq_strerror(zmq_errno())` at the error site to produce the human-readable message for logging. The error set handles control flow; the strerror call handles diagnostics. This splits what Rust unifies. | Error messages are produced at the error site rather than carried through return values. Logging at the point of failure rather than at the point of handling. This is actually more appropriate for this codebase — all errors are logged immediately and either retried or cause shutdown. |
